## Product Rules & Guardrails

This section defines the authoritative behavioral rules for the NovaTech Assistant. It governs how the assistant must respond when queried by customer service agents, and how AI coding agents (Claude Code, Copilot) must implement and extend the system. All rules are binding. Rules prefixed with **MUST** and **MUST NOT** are non-negotiable and must be enforced deterministically in code where possible. Rules prefixed with **SHOULD** represent strong defaults that require explicit justification to override.

This section is consumed by: developers, QA engineers, prompt engineers, and AI coding agents.

---

### Assistant Behavior Rules

#### Sourcing and Citation

- MUST include a `source_document` field in every JSON response, populated with the document identifier, version, and section reference. This applies even when confidence is low or when the response is a structured absence declaration.
- MUST cite sources using the canonical format: `[document_name] · [version] · [section] · updated [last_updated_at]`. Example: `POL-001 — Política de Devolução de Mercadorias · v3.1 · Seção 3.1 · updated 2024-01-15`.
- MUST NOT omit `source_document` from the response payload under any condition, including fallback, low-confidence, and out-of-scope responses.
- MUST include a `confidence_level` field in every response. Accepted values: `Alta`, `Moderada`, `Baixa`. The value MUST be computed from chunk metadata, not generated by the LLM.
- MUST set `confidence_level` to `Baixa` when the response is based exclusively on chunks from the FAQ-Atendimento (document level 4).
- MUST set `confidence_level` to `Moderada` when `has_conflict: true` in the context package, regardless of the winning chunk's document level.
- MUST include a visible `conflict_notice` field when `has_conflict: true`. The notice MUST follow this template: `"Existe outro documento na base com informação diferente para este tema: [divergent_doc_name] [divergent_doc_version], [divergent_section]. A resposta acima usa [winning_doc_name] por ser [mais recente / maior hierarquia]."` The notice MUST NOT reference the state of the document in SharePoint or any external source.

#### Factual Accuracy and Hallucination Prevention

- MUST NOT generate numeric values — including deadlines, SLA hours, freight multipliers, weight factors, discount percentages, financial thresholds, or tier eligibility figures — that are not present verbatim in the retrieved chunks.
- MUST NOT use hedging language such as "provavelmente", "normalmente", "costuma ser", "deve ser", "em geral", or "aproximadamente" in statements about deadlines, numeric values, contractual conditions, or operational procedures.
- MUST NOT extrapolate rules to cases not explicitly covered by the retrieved documentation.
- MUST NOT apply the standard 7-business-day return deadline (POL-001 Seção 3.1) to dangerous cargo (ANTT Classes 1–6). Dangerous cargo is explicitly excluded from the standard return process per POL-001 Seção 3.2.
- MUST NOT state that dangerous cargo can be returned via the standard process under any formulation of the query.
- MUST NOT invent customer tiers. Only three tiers exist: `tier Gold`, `tier Silver`, and `tier Standard` (SLA-2024 Seção 1). The tier `Platinum` does not exist and MUST NOT appear in any response.
- MUST NOT combine values from conflicting document versions in a single factual statement. Only the winning chunk's value may be stated.

#### Document Versioning

- MUST use exclusively the values from the most recent confirmed-active document version when two versions cover the same topic. For freight calculation topics, the authoritative source is PROC-042-v2 (v2.0, November 2023). PROC-042 v1.0 is revoked and MUST NOT be used as a source for numeric values.
- MUST NOT retrieve or include chunks from documents with metadata status `arquivado` in the context package.
- MUST inform the user when a more recent document version was used and a previous version exists in the base, via the `conflict_notice` field.
- MUST NOT treat a document with status `em-revisao` as a definitive source. When it is the only available document for a topic, treat the topic as having no reliable coverage and emit a structured absence declaration.

#### Scope and Fallback

- MUST respond exclusively in Brazilian Portuguese (formal register) regardless of the language of the query.
- MUST emit a structured absence declaration when no chunk exceeds the retrieval similarity threshold (cosine similarity ≥ 0.72). The declaration MUST include: the inferred topic, the reason for absence (topic not indexed / document not indexed / document under revision), and the responsible team when identifiable from formal documents.
- MUST NOT emit an absence declaration based solely on low retrieval score without verifying whether the topic belongs to the confirmed out-of-scope list. A low score may indicate a chunking problem, not a genuine absence.
- MUST prefix the response with a low-confidence warning block when the `confidence_level` is `Baixa` and SHOULD recommend supervisor escalation.
- MUST NOT provide factual content about topics that are explicitly out of scope for Phase 1: cargo insurance (no formal normative indexed), dangerous cargo freight rates (PROC-043 absent), cargo interception in transit (PROC-088 absent), individual customer contract terms, commercial negotiations, and legal claims processing.
- SHOULD suggest the responsible team or contact for out-of-scope topics when the responsible party is identifiable from a formal document (e.g., Gestão de Riscos ramal 4500 per POL-001 Seção 3.2).
- MUST NOT suggest the email address `sinistros@novatech.com.br` without an explicit caveat that this contact appears only in the informal FAQ and is not formalized in any normative document.
- MUST treat FAQ-Atendimento items 8, 22, 32, and 45 as blocked sources. These items contradict or lack normative backing. Queries covered only by these items MUST receive a structured absence declaration, not the FAQ content.

### Domain Ubiquitous Language

The following terms have precise meanings within the NovaTech domain. LLMs must not substitute synonyms, infer meanings from general usage, or translate these terms without explicit instruction.

```yaml
terms:

  - term: Cliente Gold
    definition: >
      Customer whose annual contract exceeds R$ 500,000 OR who performs more than
      200 operations per month. SLA commitments: first response within 2 business
      hours (general) or 30 minutes (critical incident); resolution within 24
      business hours (general) or 4 hours (critical incident). Entitled to a
      dedicated account manager. SLA clock does not pause outside business hours
      for critical incidents.
    source: SLA-2024 Seções 1 e 2

  - term: Cliente Silver
    definition: >
      Customer whose annual contract is between R$ 100,000 and R$ 500,000 OR who
      performs between 50 and 200 operations per month. SLA commitments: first
      response within 4 business hours (general) or 1 hour (critical incident);
      resolution within 48 business hours (general) or 8 hours (critical incident).
      No dedicated account manager.
    source: SLA-2024 Seções 1 e 2

  - term: Cliente Standard
    definition: >
      All customers not meeting Gold or Silver criteria. SLA commitments: first
      response within 8 business hours (general) or 2 hours (critical incident);
      resolution within 72 business hours (general) or 24 hours (critical incident).
      No dedicated account manager.
    source: SLA-2024 Seções 1 e 2

  - term: Frete Especial
    definition: >
      Freight modality applicable to cargo weighing more than 500 kg. Calculated
      as: Valor base × Multiplicador regional × Fator de peso. Regional multipliers
      (PROC-042-v2): Sul 1.3, Sudeste 1.1, Centro-Oeste 1.4, Nordeste 1.5, Norte
      1.8. Weight factors (PROC-042-v2): 1.0 for 500–1,000 kg; 1.15 for
      1,001–3,000 kg; 1.4 for above 3,000 kg. Additional handling time: +3
      business days. Dangerous cargo above 500 kg is NOT covered by this
      procedure — refer to PROC-043.
    source: PROC-042-v2 Seções 1, 2 e 3

  - term: Carga Perigosa
    definition: >
      Cargo classified under ANTT Resolution 5,947/2021 Classes 1 through 6:
      Class 1 (explosives), Class 2 (gases), Class 3 (flammable liquids),
      Class 4 (flammable solids), Class 5 (oxidizers and organic peroxides),
      Class 6 (toxic and infectious substances). Dangerous cargo is NOT eligible
      for the standard return process. Must be directed to Gestão de Riscos
      (extension 4500) for individual handling. NEVER apply the 7-business-day
      return deadline to this category.
    source: POL-001 Seção 3.2; PROC-042-v2 Seção 4

  - term: SLA
    definition: >
      Service Level Agreement — formal commitments between NovaTech and the
      customer defining maximum response and resolution times per customer tier.
      Measured from the ticket opening timestamp in Azure DevOps. SLA clock pauses
      outside business hours (08h–18h, business days) for general tickets. SLA
      clock does NOT pause for critical incidents of Gold customers. Violation
      penalties are defined in SLA-2024 Seção 4.
    source: SLA-2024 Seções 2 e 5

  - term: Incidente Crítico
    definition: >
      A ticket classified as critical when at least one of the following is true:
      (a) cargo with declared value above R$ 100,000 has unknown status for more
      than 6 hours; (b) dangerous cargo with any documentation or tracking
      irregularity; (c) more than 5 tickets from the same customer in the last
      24 hours about the same issue; (d) any situation involving risk to human
      safety. Critical incident SLA thresholds are lower than general ticket
      thresholds for all tiers.
    source: SLA-2024 Seção 3

  - term: CT-e
    definition: >
      Conhecimento de Transporte Eletrônico — electronic fiscal document that
      formalizes the transport contract between NovaTech and the customer. The
      CT-e number is mandatory for opening a return ticket. It is the basis for
      proportional reimbursement calculations in partial returns.
    source: POL-001 Seções 3.3 e 3.4

  - term: Gestão de Riscos
    definition: >
      Internal NovaTech department responsible for individual handling of
      requests involving dangerous cargo and other risk situations. Official
      contact: extension 4500. This is the only contact for dangerous cargo
      returns — it is formally referenced in POL-001 Seção 3.2 and may be
      cited without caveat.
    source: POL-001 Seção 3.2

  - term: Devolução Padrão
    definition: >
      Formal return process initiated by the customer via the Customer Portal
      (portal.novatech.com.br) within 7 business days of confirmed delivery in
      the tracking system. Saturdays, Sundays, and national holidays are excluded
      from the count. NOT applicable to: dangerous cargo (ANTT Classes 1–6),
      refrigerated cargo with confirmed cold chain breach, and cargo with a
      violated security seal (unless the violation was documented at delivery
      with signatures from both driver and receiver).
    source: POL-001 Seções 3.1, 3.2 e 3.3
```

### Code Generation Constraints

AI coding agents (Claude Code, GitHub Copilot) generating or modifying code in this repository MUST comply with the following constraints. Non-compliant generated code must be rejected in code review.

#### Mandatory Response Schema

Every response from the query endpoint MUST conform to this minimum schema. Generated code that omits any of these fields is invalid.

```typescript
interface AssistantResponse {
  answer: string;                     // REQUIRED. Natural language response in Brazilian Portuguese.
  confidence_level: 'Alta' | 'Moderada' | 'Baixa'; // REQUIRED. Computed from chunk metadata. NOT LLM-generated.
  source_document: {
    doc_name: string;                 // REQUIRED. Full document name. Example: "POL-001 — Política de Devolução de Mercadorias"
    doc_version: string;              // REQUIRED. Example: "v3.1"
    section: string;                  // REQUIRED. Example: "Seção 3.1"
    last_updated_at: string;          // REQUIRED. ISO 8601 date. Example: "2024-01-15"
  };
  conflict_notice?: string;           // REQUIRED when has_conflict is true. MUST follow the canonical template.
  informal_notice?: string;           // REQUIRED when source chunk is document level 4 (FAQ-Atendimento).
  stale_notice?: string;              // REQUIRED when last_confirmed_at > 6 months from current date.
  is_absence_declaration: boolean;    // REQUIRED. True when no chunk exceeded similarity threshold.
  absence_reason?: string;            // REQUIRED when is_absence_declaration is true.
  responsible_team?: string;          // REQUIRED when is_absence_declaration is true and team is identifiable.
}
```

#### Retrieval Pipeline Constraints

- MUST filter out chunks with metadata `status: "arquivado"` before building the context package. Archived chunks MUST NOT reach the LLM.
- MUST filter out chunks with metadata `status: "em-revisao"` from being used as primary sources. If a topic's only available chunk has `status: "em-revisao"`, set `is_absence_declaration: true`.
- MUST apply the similarity threshold of `0.72` (cosine similarity). Chunks below this threshold MUST NOT be included in the context package.
- MUST compute `has_conflict: true` when two or more retrieved chunks cover the same topic with divergent values, identified by matching `doc_section` metadata across different document identifiers.
- MUST select the winning chunk using the following deterministic rule: (1) lowest document level wins; (2) tie-break by `last_confirmed_at` descending. This logic MUST be implemented in code, not delegated to the LLM.
- MUST inject `is_dangerous_cargo: true` into the context package when the query contains terms associated with ANTT hazardous cargo classes. This flag MUST be detected in the pre-processing layer before retrieval.
- MUST NOT pass chunks from PROC-042 v1.0 to the LLM when PROC-042-v2 chunks are available for the same topic.
- MUST NOT include chunks from FAQ-Atendimento items 8, 22, 32, or 45 in the context package. These items are blocked at the index level.

#### Conflict Handling

- Generated code that handles conflicting documents MUST implement the winning chunk selection rule deterministically (see above).
- The `conflict_notice` string MUST be constructed by code from the metadata of the losing chunk, NOT generated by the LLM. Template:
  ```
  `Existe outro documento na base com informação diferente para este tema: ${losing_chunk.doc_name} ${losing_chunk.doc_version}, ${losing_chunk.section}. A resposta acima usa ${winning_chunk.doc_name} por ser ${winning_chunk.reason}.`
  ```
  Where `reason` is `"mais recente"` when resolved by date or `"maior hierarquia"` when resolved by level.

#### Source Validation

- Generated code MUST validate the `AssistantResponse` schema before returning to the caller. Responses missing any REQUIRED field MUST be rejected and replaced with a structured absence declaration.
- Generated code MUST NOT pass the `source_document` field to the LLM for generation. It MUST be populated from chunk metadata by the pipeline.
- Generated code MUST NOT allow the `confidence_level` field to be set by the LLM. It MUST be computed as a pure function of `chunk.level`, `chunk.status`, `chunk.last_confirmed_at`, and `context_package.has_conflict`.

#### Low Confidence Behavior

- When `confidence_level` is `Baixa`, generated code MUST prepend the following block to the `answer` field before returning: `"⚠️ Confiança baixa: esta resposta é baseada em fonte informal ou documento instável. Confirme com o supervisor antes de usar em contexto contratual."`.
- When `is_absence_declaration` is `true`, the `answer` field MUST contain the structured absence declaration with `absence_reason` and `responsible_team` populated. The `answer` field MUST NOT contain factual content about the queried topic.

#### Dangerous Cargo Guard

- Generated code implementing the response assembly MUST include an explicit check: if `context_package.is_dangerous_cargo is true` AND the assembled `answer` contains the string `"7 dias"` (case-insensitive), the response MUST be blocked and replaced with the dangerous cargo redirect message referencing POL-001 Seção 3.2 and Gestão de Riscos extension 4500.
